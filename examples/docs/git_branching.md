# Git 分支与合并入门

本文是为本项目编写的原创示例文档，用于演示检索与问答流程，内容为通用的软件工程常识。

## 分支的作用

Git 分支本质上是指向某个提交的可移动指针。创建分支几乎没有成本，所以团队通常为每个功能或缺陷修复单独开一个分支，在分支上提交改动，完成后再合并回主分支。这样主分支始终保持可发布状态，未完成的工作不会影响其他人。

## 创建与切换分支

使用 git switch -c feature-login 可以基于当前提交创建名为 feature-login 的分支并立即切换过去。只想切换到已有分支时使用 git switch main。较早的教程中常见的 git checkout -b 命令效果相同，新版本 Git 推荐使用语义更清晰的 git switch。

## merge 与 rebase 的区别

git merge 会生成一个合并提交，完整保留两条分支各自的历史，适合团队共享的分支。git rebase 会把当前分支的提交逐个重放到目标分支之后，得到一条线性历史，但会改写提交的哈希值。一条常用的规则是：不要对已经推送并被别人使用的分支执行 rebase。

## 解决合并冲突

当两个分支修改了同一文件的同一区域，Git 无法自动合并，会在文件中用 <<<<<<<、======= 和 >>>>>>> 标记出冲突区域。处理步骤是：打开文件手工保留正确的内容并删除标记，用 git add 标记冲突已解决，最后执行 git commit 完成合并。如果想放弃这次合并，可以执行 git merge --abort。

## 忽略文件

项目根目录下的 .gitignore 文件列出不需要纳入版本控制的路径模式，例如虚拟环境目录、编译产物和本地日志。需要注意的是，.gitignore 只对尚未被跟踪的文件生效；已经提交过的文件需要先用 git rm --cached 从索引中移除，忽略规则才会起作用。
