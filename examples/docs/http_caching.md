# HTTP 缓存机制说明

本文是为本项目编写的原创示例文档，用于演示检索与问答流程，内容为通用的 Web 开发常识。

## 强缓存与 Cache-Control

服务器可以通过响应头 Cache-Control 控制浏览器缓存。Cache-Control: max-age=3600 表示响应在 3600 秒（1 小时）内是新鲜的，期间浏览器直接使用本地副本而不发起请求，这被称为强缓存。public 表示中间代理也可以缓存，private 表示只允许用户自己的浏览器缓存。

## no-cache 与 no-store

no-cache 并不是“不缓存”：浏览器可以保存副本，但每次使用前都必须向服务器验证是否仍然有效。no-store 才表示完全不保存任何副本，适合包含敏感个人数据的响应。两者经常被混淆，配置缓存策略时要特别区分。

## 协商缓存与 ETag

当缓存过期或要求验证时，浏览器会进行协商缓存。服务器在首次响应中返回 ETag（资源内容的版本标识），浏览器下次请求时在 If-None-Match 头中带上这个值。如果资源没有变化，服务器返回 304 Not Modified 且不带响应体，浏览器继续使用本地副本，从而节省带宽。

## Last-Modified 的局限

另一种协商方式是 Last-Modified 与 If-Modified-Since，按资源的最后修改时间判断。它的精度只到秒，一秒内多次修改无法区分；而且文件内容不变但修改时间变化时也会导致缓存失效。因此在可以计算内容摘要的场景下，ETag 通常更可靠。

## 静态资源的常见策略

对文件名中带有内容哈希的静态资源（例如 app.3f9a2c.js），可以设置很长的 max-age，例如一年，并加上 immutable；内容更新时文件名随之改变，自然绕过旧缓存。对 HTML 入口页面则通常使用 no-cache，保证用户总能拿到引用最新资源的页面。
