# 关系数据库索引基础

本文是为本项目编写的原创示例文档，用于演示检索与问答流程，内容为通用的数据库常识。

## 索引的作用与代价

索引是一种额外维护的数据结构，让数据库不必扫描整张表就能定位到满足条件的行。大多数关系数据库默认使用 B+ 树索引，它在等值查询和范围查询上都表现良好。代价是索引占用存储空间，并且每次插入、更新或删除数据时都需要同步维护索引，写入会变慢。

## 复合索引与最左前缀

在多个列上建立的索引称为复合索引，例如在 (last_name, first_name) 上建索引。查询条件必须从最左边的列开始连续使用，索引才能发挥作用：只按 last_name 查询可以用到它，只按 first_name 查询通常用不到。这条规则被称为最左前缀原则。

## 索引失效的常见情况

即使列上有索引，以下写法也常常导致无法使用索引：对索引列使用函数或运算，例如 WHERE YEAR(created_at) = 2024；以通配符开头的模糊匹配，例如 LIKE '%abc'；以及列类型与比较值类型不一致引起的隐式类型转换。改写为对常量做计算或使用范围条件，通常可以恢复索引的使用。

## 用 EXPLAIN 查看执行计划

在查询语句前加上 EXPLAIN 可以查看数据库打算如何执行它，包括是否使用索引、使用哪一个索引以及预计扫描的行数。如果看到全表扫描且预计行数接近表的总行数，通常说明缺少合适的索引，或者查询写法让索引失效。

## 何时不建索引

数据量很小的表、很少被用作查询条件的列，以及取值重复度很高的列（例如只有两种取值的状态字段）通常不值得单独建立索引。写入频繁而查询很少的表也要谨慎添加索引，因为维护成本可能超过查询收益。
