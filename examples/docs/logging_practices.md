# 应用日志实践

本文是为本项目编写的原创示例文档，用于演示检索与问答流程，内容为通用的软件运维常识。

## 日志级别

常见的日志级别从低到高依次是 DEBUG、INFO、WARNING、ERROR 和 CRITICAL。DEBUG 用于开发时的详细诊断信息；INFO 记录正常的业务事件；WARNING 表示出现了异常情况但程序仍能继续；ERROR 表示某个操作失败；CRITICAL 表示整个程序可能无法继续运行。生产环境通常把输出阈值设为 INFO 或 WARNING。

## 结构化日志

结构化日志把每条日志写成机器可解析的格式，最常见的是每行一个 JSON 对象，包含时间戳、级别、消息以及请求编号等字段。与纯文本相比，结构化日志可以直接按字段过滤和统计，便于在日志平台中检索同一请求经过的所有服务。

## 不应写入日志的内容

日志通常会被复制到多个系统并保存较长时间，因此不能写入口令、访问密钥、完整的银行卡号或身份证号等敏感数据。必须记录时应进行掩码处理，例如只保留卡号的后四位。在代码审查中检查日志语句是否泄露敏感字段，是一项低成本、高收益的措施。

## 日志轮转与保留期

日志文件如果不加控制会无限增长并占满磁盘。日志轮转按大小或时间切分文件，例如每天生成一个新文件，并只保留最近 14 天的文件，更早的自动删除或归档。保留期应同时满足排查问题的需要和数据保护方面的要求。

## 关联编号

在分布式系统中，一个用户请求可能经过多个服务。在请求入口生成一个唯一的关联编号（correlation ID），并在调用下游服务时通过请求头传递，每个服务都把它写入日志。排查问题时只需按这个编号搜索，就能串起完整的调用链路。
