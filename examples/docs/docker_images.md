# Docker 镜像分层与构建缓存

本文是为本项目编写的原创示例文档，用于演示检索与问答流程，内容为通用的容器技术常识。

## 镜像由只读层组成

Dockerfile 中的 RUN、COPY、ADD 等指令都会生成一个新的只读层，镜像就是这些层按顺序叠加的结果。容器启动时在最上面再加一个可写层，容器内的修改只写入这一层，不会改变镜像本身。多个镜像共享相同的底层时，磁盘上只保存一份。

## 构建缓存如何失效

构建时 Docker 会逐条检查指令：如果指令文本和它依赖的文件都没有变化，就直接复用缓存层。一旦某一层的缓存失效，它之后的所有层都必须重新构建。COPY 指令的缓存取决于被复制文件的内容校验和，只要文件内容变了，这一层及后续层都会重建。

## 利用顺序提高缓存命中

推荐把变化少的步骤放在前面。以 Python 项目为例，先只复制 requirements.txt 并执行 pip install，再复制其余源代码。这样修改业务代码时，安装依赖那一层仍然可以命中缓存，构建时间可以从几分钟缩短到几秒钟。

## .dockerignore 文件

执行构建时，Docker 会把构建上下文目录发送给构建引擎。.dockerignore 的写法与 .gitignore 类似，用来排除 .git 目录、虚拟环境、测试数据等不需要的文件。排除它们既能减少发送的数据量，又能避免无关文件的变化导致 COPY 层缓存失效。

## 多阶段构建

多阶段构建在一个 Dockerfile 中使用多个 FROM。前一阶段使用包含编译工具的完整镜像生成产物，最后一阶段从精简的基础镜像开始，只用 COPY --from 复制需要的产物。最终镜像不包含编译工具和中间文件，体积更小，攻击面也更小。
