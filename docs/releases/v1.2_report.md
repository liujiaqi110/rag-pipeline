# v1.2 交付报告：评估与可复现性

状态：已在本地完成修改与验证，**尚未提交，也未推送**。

## 1. 修复的缺陷

| 缺陷 | 处理 |
|---|---|
| `compute_recall` 实际只判断文件级命中（top-K 中有任一 Chunk 来自期望文件即算命中），却被当作 Recall@K | 更名为 `compute_source_hit`，报告字段与表头改为 SourceHit@5/10。新增 Chunk 级 Recall@K、Hit@K、MRR、nDCG@K 和证据槽覆盖（`ragas_eval/retrieval_metrics.py`） |
| `search_hybrid`（union_safe）排序以 BM25 名次为主键，并丢失名次标注，导致 Dense 独有的候选被截断 | 更名为 `search_hybrid_legacy_union_safe`，保留旧名作为别名供历史代码调用，标注为 Legacy 并写明已知缺陷；单元测试复现了这些缺陷，并验证同样的输入经 RRF 处理后正确 |
| 旧报告与代码把 union_safe 称为 “RRF+safe” 或 “RRF fusion” | 已删除这些说法；测试断言相关字符串不再出现 |
| 正式服务的 RRF 参数只隐含在默认值里 | 新增 `rag_retriever.SERVICE_RRF = RRFParams(k=60, bm25_pool=25, dense_pool=25)` 并显式传入 |
| `rag_config.yaml` 中多数字段没有代码读取，却看起来像在控制系统 | 逐字段注明读取者；新增 `service_retrieval` 说明段，由回归测试保证与代码一致；旧字段标注为 LEGACY；新增 `docs/CONFIG.md` |
| `scripts/03` 的 `load_config()` 从未被调用 | 已在文档中说明（行为未改变） |
| 依赖清单列出了公开代码并不使用的 ragas、openai、langchain 等包 | 新增 `requirements.txt` 和 `requirements-ci.txt`；`requirements-v1.1.txt` 注明只是研究环境记录 |
| v1.1 的两个安全层测试包含研究题目原文和私有课程文档名 | 替换为虚构的文档名和问题，测试逻辑不变 |

**正式检索没有退化**：用研究题集 48 题在私有索引上比较修改前后的 top-10，BM25、Dense、RRF 三种模式全部逐题一致（48/48，结果哈希相同）。正式入口的真实问答也正常（status ok，带 1 条有效引用）。
