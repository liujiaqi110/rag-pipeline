### 评分校准（v1.0.1）

v1.0 有 22 条答案存在分歧：确定性检查与自动评判结论冲突。这些分歧由 AI 助手对照原文做了审计（**不是人工复核**），结论如下：

- 确定性检查过严的有 10 条；
- 本地评判过宽的有 9 条。

据此修订了评分规则（v2）：逐字匹配类与等价表达类分开处理，增加别名归一化，拒答识别改为按句判断。在 fixed_39 的 22 条分歧上，v2 与审计结论一致的有 14/22。v2 重新评分后，两臂的结果为：

| 臂 | correct | partial | incorrect | false_refusal | uncertain |
|---|---|---|---|---|---|
| A Dense | 22 | 16 | 0 | 1 | 0 |
| B RRF | 25 | 14 | 0 | 0 | 0 |

在 56 条没有分歧的答案上，规则修改后类别变化为 0 条。不过它们与设计规则时用的是同一批题，不构成独立验证。

v2 剩余分歧的主要来源是参考答案没有区分“必答事实”和“补充信息”，确定性规则无法从文本本身判断。

### 评分 v3：事实重要性标注（v1.0.2）

v3 为参考答案中的每个事实标注重要性（必答 / 补充 / 不确定），再由本地 qwen2.5:7b 逐事实评判。事实标注由 AI 助手依据 GT 证据完成，属于自动化结果，未经人工确认。

| 比较对象 | 分歧条数 | 与 AI 助手审计结论一致 |
|---|---|---|
| v2（v1.0.1） | 22（fixed_39） | 14/22 |
| v2（v1.0.2 重算） | 24（fixed_39 的 22 条 + 扩展题 q001 的 2 条） | 14/24 |
| v3（v1.0.2） | 24 | 18/24 |

已知的 v3 问题：

- 逐事实评判对很短的事实不可靠，例如回答已逐条写出步骤，评判器仍给出 no 或 partly，v3 剩余的不一致主要来自这一点；
- v3 只检查必答事实是否出现，不检查回答中多出来的无依据陈述。

**评分版本不能混用**：上文 v1.0 表格使用 `judge_v1.0`，“评分校准”表格使用 v2，下文 v1.0.2 稳定性表格中的答案类别使用 v3。三者的数字不能直接相加或相减。

## D. 稳定性与安全

### 新 Prompt 被回归门禁拒绝（v1.0.1）

`rag_v1.1` 针对拒答失败做了改动：要求先判断资料是否直接回答了所问对象，禁止用其他对象的特点推断原因，完全拒答时只输出拒答句。

回归门禁在 20 题子集上比较 B（RRF + rag_v1.0）与 C（RRF + rag_v1.1），结果**未通过**：

| 门禁条件 | 结果 |
|---|---|
| 不新增可答题误拒 | **未通过**：q011 在 C 中变为拒答 |
| 答案质量下降不超过 1 题 | 通过 |
| 正确拒答不减少 | 通过 |
| 编造不增加 | 通过 |
| 被拦截引用不增加 | 通过 |

v1.0.2 用多个 seed 重复验证（门禁结论不变）：

- c041 在 v1.1 下原样输出了 Prompt 模板中的占位文字（**模板泄漏**）：3 个 seed 的全部 6 次运行（含 seed 42 的重复）都出现。下表按每个 seed 计 1 次，记为 3；
- q003 在 3 个 seed 下的自动评分都比 v1.0 低。研究报告的复核认为这主要是评判噪声：两者首句相同，而 v1.1 的引用反而更准确。因此这一条不作为拒绝 v1.1 的依据；
- q011 在 v1.1 下被 v3 归为“证据不在上下文中的合理拒答”，而不是误拒。v1.0.1 门禁按当时的规则判为未通过，这一结论保留不改。

因此正式服务保留 `rag_v1.0`。拒答和引用问题改由确定性的软件安全层处理（见下文）。

### 多 Seed 重复生成（v1.0.2）

门禁 20 题，每题在 seed 42、43、44 各生成 1 次；q011、c041、q004b、q009 在 seed 42 下另外重复 3 次。本节的答案类别都使用**评分 v3**。

| 指标 | B：RRF + rag_v1.0 | C：RRF + rag_v1.1 |
|---|---|---|
| 可答题 correct，按 seed 42 / 43 / 44 | 4 / 4 / 4 | 3 / 3 / 3 |
| 无答案题正确拒答，按 seed | 7 / 7 / 7 | 8 / 8 / 8 |
| 幻觉（编造、无依据标识符、来源错配） | 3 | 3 |
| 引用错误 | 9 | 3 |
| 拒答仍带引用：原始 → 软件清理后 | 6 → 3 | 3 → 0 |
| Prompt 模板泄漏 | 0 | 3 |
| 端到端耗时 ms：均值 / p50 / p95 | 3757.2 / 2875.7 / 9510.16 | 3392.7 / 3219.11 / 7260.64 |
| 跨 3 个 seed 逐字相同 / 类别相同 | 16/20 / 20/20 | 16/20 / 20/20 |

同 seed 成对比较（60 对）：C 更好 6 对，C 更差 3 对，相同 51 对。

结论：temperature 0 并固定 seed 仍不能保证逐字复现，本批 20 题中有 4 题在不同 seed 下文本不同；v1.0.3 的剩余风险清单把它概括为：相同设置下约 10% 的回答不能逐字复现（依据 v1.0.1 / v1.0.2）。不过本批题的答案类别是稳定的。

## 在本仓库中能复现什么

- 研究题集、私有语料和生成记录都不公开，上述数字无法在本仓库直接复现。
- 公开示例知识库上的真实问答可以复现：`python -m ragas_eval.example_qa`，它只做确定性的功能检查，不给答案质量打分。
- 本仓库**没有** RAGAS 评估，也没有 Faithfulness 或 Answer Relevancy 分数，见 `limitations.md`。
