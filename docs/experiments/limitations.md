# 局限与适用范围

## 评估本身

- **没有人工验证**：研究题集的 Ground Truth 由机器审核（`human_approved=false`），答案由与生成相同的本地模型自动评判。分歧审计由 AI 助手完成，不是人工复核。
- **没有独立验证集**：研究项目准备了独立验证集的标注包，但至今没有标注人完成标注和冻结。holdout_6 与 fixed_39 的知识点重复，也不算独立验证集。所有规则、Prompt 和融合参数都是在同一批题上设计和比较的。
- **规模很小**：39 道可答题加 8 道无答案题，语料只有 7 份文档、149 个子 Chunk。跨文档题只有 5 道，单题变化就会造成很大的百分比波动。
- **不是生产级正确率**：本项目的任何数字都不能当作生产环境的正确率、幻觉率或“零幻觉”证据。
- **公开示例只是功能验证**：`examples/` 中的 6 篇原创文档和 22 道题用来验证流程能否跑通。语料小、问题直接，检索指标接近饱和，**不能**代表研究题集，也不能证明模型的泛化能力。

## RAGAS

本仓库**没有** RAGAS 自动评估能力，包名 `ragas_eval` 是历史遗留。

`requirements-v1.1.txt` 中的 `ragas` 只是研究环境的版本记录，公开代码没有导入它。仓库中没有执行过任何 Faithfulness、Answer Relevancy 或 Context Precision 评估，也不报告这些分数。如果以后接入，需要单独实现，并重新在本地模型上实际运行后才能报告结果。

## 系统层面

- 安全层只保证引用 ID 真实存在于上下文中，**不保证**引用在语义上支持该陈述。
- 来源保护只识别显式写法：“<文档> 中/里”“根据 <文档>”“（<文档>）”。口语化的指代不会触发。
- 生成存在不确定性：temperature 0 并固定 seed 时，仍有一部分回答不能逐字复现。
- 跨文档列举题常常凑不齐全部文档的证据；查询分解和多样性重排都没有带来净收益。
- 模型可能把资料中的“用途”说成“选择理由”这类无依据推断；安全层不改写语义。
- 检索不利用文件名或元数据；指定文档的问题如果检索不到目标文档，只会如实报告“检索不足”。

## 数据与发布

- 研究语料、索引、题集和生成记录来自私有课程笔记，可能涉及版权，**不公开**。正式服务通过 `RAG_DATA_DIR` 读取私有数据目录。
- `scripts/10_eval_retrieval.py` 中的 `search_hybrid_legacy_union_safe` 和 `compute_source_hit` 是历史实现，只为可复现而保留，不推荐使用。
